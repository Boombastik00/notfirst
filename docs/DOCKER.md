# docker простыми словами

## что это и зачем

наш проект — это три программы:

- db — база данных postgresql, хранит истории, теги, пользователей
- api — бэкенд на python, отдаёт данные
- web — фронтенд на next.js, то что видно в браузере

без docker каждую пришлось бы ставить в систему руками: нужные версии, настройки,
права. docker упаковывает каждую программу в контейнер — изолированную коробку,
внутри которой уже есть всё необходимое. коробки не трогают систему и друг друга

docker-compose.yml — это список коробок проекта: «подними базу, бэкенд и фронтенд
и соедини их». одна команда запускает всё

главный бонус: на будущем сервере запускаются ровно те же коробки, поэтому
«у меня работало а на сервере нет» не случится

## установка (была сделана один раз)

    sudo apt update
    sudo apt install -y docker.io docker-compose
    sudo usermod -aG docker valeria

после этого нужно выйти из сеанса и зайти снова (или перезагрузиться), чтобы
группа docker применилась. проверка: `docker ps` отвечает без sudo

## повседневные команды

запустить весь проект (первый раз долго, собирает коробки):

    docker compose up --build

запустить в фоне и освободить терминал:

    docker compose up -d

остановить всё:

    docker compose down

посмотреть что сейчас запущено:

    docker compose ps

логи бэкенда (или web / db):

    docker compose logs -f api

полностью снести коробки и данные базы (осторожно, удалит данные):

    docker compose down -v

## что важно помнить

- остановка docker ничего не удаляет, данные базы живут в volume db_data
- сам проект (код) docker не меняет, коробки только читают файлы
- если порт 5432 или 3000 занят другой программой — надо освободить
