# как включить вход через google

вход работает через oauth 2.0: пользовательница подтверждает вход в своём
google-аккаунте, мы получаем только id, email, имя и аватар. пароль от gmail мы
не запрашиваем и не видим никогда

## шаг 1 создать oauth-клиент (один раз, ~5 минут)

1. зайди на https://console.cloud.google.com под тестовым google-аккаунтом
2. сверху слева нажми выпадающий список проектов → «новый проект» → имя
   `notfirst` → создать → выбрать его
3. слева меню «api и сервисы» → «экран согласия oauth» (oauth consent screen):
   - тип пользователя: внешний
   - название приложения: не первая
   - email поддержки: свой
   - дальше-дальше-готово, области (scopes) добавлять не нужно на этом экране
4. «учетные данные» → «создать учетные данные» → «идентификатор клиента oauth»:
   - тип: веб-приложение
   - разрешенные uri перенаправления: вставь ровно эту строку

         http://localhost:3000/api/v1/auth/google/callback

5. получишь `идентификатор клиента` (client id) и `секрет` (client secret) —
   сохрани их

## шаг 2 вписать секреты

в корне проекта рядом с docker-compose.yml создай файл `.env` (он не попадает в
git) и заполни:

    GOOGLE_CLIENT_ID=1234-abc.apps.googleusercontent.com
    GOOGLE_CLIENT_SECRET=secret
    SESSION_COOKIE_SECRET=любая случайная длинная строка

## шаг 3 узнать свой google_sub и назначить себя админом

пока вход включен но admin_google_subы не заполнены работает так: зайди через
сайт, затем посмотри свой id в базе

    docker compose exec db psql -U notfirst -c "select i.provider_sub, i.email, u.role from auth_identities i join users u on u.id = i.user_id;"

скопируй google_sub и добавь в тот же `.env`:

    ADMIN_GOOGLE_SUBS=вставь_сюда_google_sub

перезапусти api (`docker compose restart api`), выйди и войди снова — роль
станет admin и откроется /admin

## проверка

- http://localhost:3000/login → «продолжить с google» → согласие → возврат на
  главную
- http://localhost:3000/api/v1/auth/me показывает твои данные
- админка: http://localhost:8000/admin/ — напрямую у api. не через порт 3000:
  за прокси фронтенда админка ссылается на себя внутренним docker-именем api
  которое браузер не знает. в продакшене единая точка входа и проблемы нет

когда появится домен нужно будет добавить в google cloud ещё один uri
перенаправления с этим доменом и поменять BASE_URL
